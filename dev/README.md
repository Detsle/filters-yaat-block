# DEV-фильтры Я@ Block

Каталог `dev/` используется как временное рабочее место для правил, которые сейчас тестируются в локальной DEV-сборке.

## Состояние после переноса в релиз

После того как правила проверены и утверждены, их нужно перенести в соответствующие файлы `filters/*.css`, обновить корневой `filters-manifest.json` и увеличить patch-версию базы фильтров.

Затем из каталога `dev/` удаляются все временные файлы. В каталоге должен остаться только этот `README.md`.

## Начало нового цикла тестирования

Когда начинается тестирование нового домена или категории:

1. Создать в `dev/` CSS-файл только для тестируемого домена/категории.
2. Создать или обновить `dev-manifest.json`: revision, generatedAt, SHA-256 и размер каждого DEV-файла.
3. Вносить в DEV только проверяемые экспериментальные правила. Не изменять утверждённые production-фильтры без отдельной необходимости.

После утверждения правил перенести их в production, обновить production-манифест и снова очистить `dev/`, оставив только README.

## Изоляция релиза

Релизная сборка загружает корневой `filters-manifest.json` и файлы из `filters/`. Она не запрашивает `dev/` и не использует `dev-manifest.json`. DEV-правила не должны попадать в релизную сборку.

Примечание: `dev/` — каталог внутри репозитория, а не отдельная Git-ветка. На момент обновления в репозитории используется ветка `main`.
