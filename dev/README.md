# DEV-фильтры Я@ Block

Каталог `dev/` предназначен для экспериментальных CSS-правил локальной DEV-сборки расширения.

## Базовая конфигурация

Файл `dev-manifest.json` публикуется вместе с каталогом. Начальное состояние:
- `revision: 0` — тестовые правила ещё не опубликованы;
- `categories: {}` — пустой набор DEV-правил.

Локальная DEV-сборка загружает production-базу из корневого `filters-manifest.json` и ветки `main` так же, как релизная версия. DEV-файлы загружаются отдельно по этому манифесту и хранятся отдельно от production-фильтров.

## Добавление тестовых правил

1. Создать в `dev/` CSS-файл только для нужной категории, например `dev/yandex-market.css`.
2. Внести путь файла, категорию, его точный UTF-8-размер и SHA-256 в `dev-manifest.json`.
3. Увеличить целочисленную `revision` и обновить `generatedAt`.
4. Опубликовать CSS-файл и манифест в `main`.

Поддерживаются только CSS-файлы размером до 512 KiB. В них запрещены `@import`, внешние ресурсы через `url()`, `expression()`, JavaScript-схемы и теги script. DEV-сборка проверяет полный набор по размеру и SHA-256 и сохраняет его отдельным атомарным пакетом.

## Применение и изоляция

DEV-CSS накладывается поверх соответствующего production CSS только при включённом переключателе «DEV-режим». При выключении переключателя остаются только production-правила. DEV-пакет не может заменить или отключить production-базу.

Кнопка «Обновить сейчас» обновляет production-базу. Кнопка «Обновить DEV» независимо проверяет DEV-манифест и тестовые файлы. Проверка выполняется также при запуске/установке и далее в общем шестичасовом цикле.

Релизная сборка 1.1 не содержит DEV-загрузчика и не обращается к каталогу `dev/`. Поэтому файлы этого каталога не влияют на опубликованную production-версию.

После утверждения тестовых правил перенести их в соответствующие `filters/*.css`, пересчитать production-манифест и его версию, а временные CSS-файлы удалить. Сам файл `dev-manifest.json` остаётся с пустым набором категорий, чтобы отдельная DEV-сборка могла штатно проверять отсутствие активных тестовых правил.

Примечание: `dev/` — каталог внутри репозитория `Detsle/filters-yaat-block`, а не отдельная Git-ветка.
